# VKOS 3.0 na nuvem: CORE do Jesse + workspaces de clientes com login

## Contexto

O 3.0 vinha sendo pensado como acessibilidade do produto local. Em 2026-07-22, depois de fechar o entendimento de compliance com a Anthropic (uso pessoal do Claude do Jesse é permitido, cliente usa credencial própria de Claude Team ou Gemini, sem compartilhamento de credencial entre pessoas), o Jesse decidiu mudar o rumo: o 3.0 é a versão nuvem.

## Decisão

O VKOS Hub vira uma plataforma na VPS (Google Cloud como casa, arquitetura portável) com dois lados sobre o mesmo código:

- **VKOS HUB CORE**: painel interno, só o Jesse loga, único lugar onde o Claude pessoal dele existe. Administra modelos de workspace, workspaces de clientes, logins, features e motores.
- **Workspaces de clientes**: cada cliente recebe login pro workspace dele, montado a partir de um modelo, com features ligáveis e desligáveis pelo CORE. O motor de IA do cliente é Claude Team com credencial própria dele (gerenciada no cofre com consentimento) ou Gemini via Vertex AI, medido por workspace. Nunca o Claude do Jesse.

As capacidades do 2.x (Cockpit, Criador Visual, Site Guiado, CRM, Calendário, Automações, Conexões, Leads, IDE) viram features modulares com manifesto, o sistema monta como lego. O instalável local para leigo sai do produto.

Plano completo em `planos/vkos-3-nuvem/`. Separação de segurança central: o runtime de cliente não tem acesso físico à credencial do Jesse nem ao cofre, só ao serviço motor.

## Por quê

- O Jesse quer acessar o próprio hub de qualquer lugar e entregar workspaces prontos sem instalação na máquina do cliente.
- O crédito e a stack do Google Cloud (VM, Vertex, Storage, Secret Manager) cobrem tudo unificado.
- O modelo de credencial por cliente é o único limpo nos termos da Anthropic, e o Gemini cobre o cliente sem conta de IA.
- Features como módulos permitem vender workspaces sob medida (exemplo discutido: modelo "Automobilístico") e crescer por encaixe, sem reescrever o núcleo a cada feature nova.
